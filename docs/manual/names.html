Camera & position names

Give the five cameras and their fifty position slots readable names — and save whole sets for different shows.

By default a camera is "Cam 1" and a slot is just a number. The PC app lets you name all 5 cameras and all 50 position slots (10 per camera) — so "Cam 2" becomes "Stage Left" and slot 3 becomes "Wide on lectern". Names are display labels only; they don't change any camera behaviour.

Names are the one thing the app owns Unlike positions and calibration (which live on the mounts), names live on the PC, in Documents/PTS/ as JSON files. That's why naming is an app feature, and why you can keep different name sets for different productions. See How it fits together.

Editing a name

Click a camera's name or a position slot's label in the PC app and type. The change shows everywhere in the app immediately.

Editing a name updates a working copy only — it does not touch your saved name files (not even the defaults) until you explicitly save. So you can rename freely while setting up without disturbing a saved set.

Save, load, set defaults

The controls live in Config → Camera & Position Names.

ButtonWhat it does
Save…Writes the current names to a .json file you choose. Use this to keep a set for a show.
Load…Loads a saved .json set, replacing the current names.
Set as DefaultsMakes the current names the set that loads automatically every time the app starts.

The file picker defaults to your Documents/PTS folder, where all name sets live.

How startup works

  • Every time the app opens, it loads the names from Default.json.
  • As you edit, changes are kept in a working copy (temp.json) — your saved sets and the defaults are left alone.
  • To make edits stick across restarts, press Set as Defaults (updates Default.json), or Save… to a named file you can re-load later.
Per-show name sets Set up naming for a production once, Save… it as e.g. Autumn-Gala.json, and next time just Load… it. Keep a neutral house set as your Defaults so every fresh start is clean.
First run If Default.json doesn't exist yet, the app seeds it from the current names, so there's always a defaults file to fall back on.
