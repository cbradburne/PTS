Configuration reference

Every setting in the PC app's Config dialog, and where each one is stored.

Open Config in the PC app. It has a General tab for app-wide and connection settings, and a tab per camera (Camera 1–5) for that mount's hardware and speeds.

Where settings live Per-camera settings (orientation, speeds, stall thresholds, limits) are written to the mount's own memory — the app just reads and edits them, and they follow the mount anywhere. Only the connection settings and camera labels are saved on the PC. See How it fits together.

Slider angle

The rail is not always level. Rigged off a truss or up a raked seating bank it climbs, and then travelling along it changes the camera's height as well as its position — so the tilt needed to hold a subject changes too.

The mount cannot sense this. Tell it the angle and it resolves the rail into along and up components, and every look-at aim accounts for the climb. Leave it at 0 on a rail the mount is really climbing and the tracking is correct at the end you calibrated from and drifts progressively as the camera travels away from it.

WhereHow it is set
PC appA number box on the camera's tab, alongside the other hardware settings.
Web appA number box in the extended config panel, like the other numeric fields there.
Hub displayA Slider Angle row on the config screen: − and + step by half a degree, 0 levels it.
Measuring it A phone's spirit level along the rail is close enough. The tilt only has to be right to about half a degree for the tracking to hold across the full length — which is why the console steps in halves.
When a setting reaches the mount The clients commit at different moments, and it is worth knowing which you are using.
  • PC app and web app — a number box sends when you leave it: press Enter, or click elsewhere. Typing alone changes nothing, so a half-typed number is never sent.
  • Hub display — the −/0/+ buttons only change what is on screen. The value is sent when you press Apply, switch camera, or leave the config screen.
Until the mount has told a client what its angle currently is, that client will not send one — so toggling an unrelated switch cannot accidentally level a rail the client has not yet been told about.

StallGuard thresholds

How much load the axis must feel before the mount decides it's hit an end stop, for the slider and zoom (0 = sensitive, 255 = coarse). Tune these if homing stops early (too sensitive) or pushes into the stop (too coarse). Used by homing and Find Limits.

On a climbing rail the threshold is adjusted for you Gravity is load. Driving up a tilted rail the motor is already working before it touches anything, and driving down it is being helped — so one fixed threshold either trips early going up or misses the stop coming down. The mount compensates using the slider angle above, in the direction it is currently travelling, so tune the threshold on a level rail and it holds on a raked one.

Find Limits

Drives the slider and zoom to their end stops to measure the axis range in millimetres. Required before using look-at tracking. Hidden if the camera has no slider.

The seek runs at a deliberately gentle speed and ramp. A stall is detected from motor load, and a carriage arriving fast reads as a stall slightly late — so a slow approach finds the true end rather than a point past it.

Both ends are inset by 30 mm A tilted rail needs more motor current and a less twitchy stall threshold to stop the carriage stalling part-way along a move — and a less sensitive stall detector notices the end stop later. By the time an end is recorded the carriage has already run into it, so the stored limit sits somewhere inside the stop and every later move to that limit grinds against it.

Pulling each usable end back by 30 mm costs 60 mm of travel in total and means a move to either limit stops short of the stop rather than against it. The home end takes the same inset as the far one: position 0 is the home stall, which is a point the carriage reached by running into something, so it is no safer to drive back to than the far end is. Until 2026-09-01 only the far end was inset, and a look-at run parked hard against the stop at one end and about 32 mm short at the other.

Home is still position 0 — the datum has not moved, only the usable range. The millimetre range the app shows after a limit find is the usable one.

It is a setting. Config → camera tab → End margin, per mount, 3–200 mm, stored on the mount and applied at the next Find Limits. 30 mm is a workaround for late detection, not a measurement, so the right value is whatever your rig turns out to need: lower it, run Find Limits, and listen at each end. If the carriage touches, go back up. It is adjustable precisely so that finding out does not cost a Teensy flash each time.

This is a workaround for late detection, not a fix for it. A stall threshold that trips at the stop with the current the tilt demands, or a physical switch, would let it go back to a millimetre or two.
Homing and Find Limits move the axis to its physical limit Make sure the mount is clear to move before running either.
Saving Changes to per-camera settings are written to the mount when you apply them; the app fetches the mount's live values each time you open Config, so what you see is what the mount actually holds.
